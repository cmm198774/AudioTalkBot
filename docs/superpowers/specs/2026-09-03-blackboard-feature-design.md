# 小黑板功能设计文档

日期：2026-09-03
状态：已批准

## 背景与目标

课堂场景下，老师一边讲课，一边希望"黑板"上呈现**与讲的话不同**的内容
（如把口语讲解提炼成公式、题目原文、知识要点）。

Realtime 模型的 `modalities` 只能控制同一段回复用声音还是文字呈现，
音频与文字是同一内容的两种形态，做不到"说的"和"写的"分离。
因此本功能把输出拆成两条通道：

- **语音通道**（现有）：realtime 模型全双工对话，低延迟
- **板书通道**（新增）：同一回复内，用格式标记把特定内容路由到黑板显示，并抑制其语音

## 核心机制

后端拼接一段固定的板书指令（`BOARD_PROMPT`，与用户人设分离）：

> 当需要呈现板书内容时，单独输出一段以 `[text]:` 开头的内容，
> 例如 `[text]:勾股定理：a² + b² = c²`

模型某个回合若以 `[text]:` 开头回复，即视为板书回合。

### 实测依据（2026-09-03，专属工作空间端点）

| 观测项 | 结果 |
|---|---|
| `[text]:` 格式遵守 | ✅ 回合转写严格以 `[text]:` 开头 |
| 首个文字增量到达 | 约 0.38 秒 |
| 首个音频增量到达 | 约 1.44 秒（**文字领先音频约 1 秒**） |
| 板书回合仍生成音频 | ✅（9.8 秒，模型会"念"板书，必须掐断） |

文字领先音频约 1 秒，意味着可以在任何音频送达前端之前完成检测并丢弃音频。

## 行为规格

### 后端

1. **指令拼接**：`/ws/chat` 的 `start` 与 `update_settings` 下发
   `session.update` 时，instructions = 用户人设 + `BOARD_PROMPT`。
   人设的编辑、持久化完全不受影响；板书指令对用户不可见。
2. **回合级板书检测**（`RealtimeBridge`）：
   - 每个回复回合累积转写文本。回合开始时尚未判定：
     累积内容只要仍是 `[text]:` 的可能前缀（去除首部空白后），
     就暂缓把转写增量发给前端（避免字幕漏出 `[tex…` 碎片）。
   - 一旦确认以 `[text]:` 开头 → 进入板书模式：
     - 丢弃该回合后续所有 `response.audio.delta`
     - 向前端发送一次 `interrupt`（清空可能已排队的音频，双保险）
     - 转写增量去掉 `[text]:` 前缀后，以 `{"type": "board", "delta": ...}` 下发
   - 累积内容与 `[text]:` 前缀分道扬镳（或回合结束仍未凑满 7 字符）
     → 判定为普通回合，把暂存的增量照常被 `transcript` 消息补发。
   - `response.done` 时复位板书模式与暂存。
3. **持久化**：板书回合的助手文本**连同 `[text]:` 原文**落盘，
   保证切换会话恢复历史时模型知道自己写过什么。
4. **顺带修复**：`update_settings` 只改输出模式（未带 prompt）时，
   原实现会向模型下发空 instructions 清空人设；改为回读会话存储的
   人设后再拼接板书指令下发。

### 前端

1. **布局**：主区域上下结构 —— 小黑板（上）+ 可拖拽分割线 + 聊天区（下）。
2. **分割线**：按住上下拖动调整两区高度；默认 1:1；比例存入
   localStorage，刷新后恢复。
3. **开关**：头部 📋 按钮切换黑板显隐（默认开）；关闭时聊天区占满。
4. **内容**：收到 `board` 增量 → **追加**到黑板末尾（越写越多），
   自动滚动到底部；黑板右上角"清空"按钮手动擦除。
5. **样式**：深绿底、白色粉笔字。
6. **字幕隔离**：板书内容不进字幕区；普通回合不受任何影响。
7. **历史渲染**：助手消息以 `[text]:` 开头时，渲染为板书样式气泡
   （📋 前缀 + 去掉标记的原文）。
8. **重置时机**：结束对话、切换会话时黑板清空。

### 前端消息协议（新增）

| 方向 | 消息 | 说明 |
|---|---|---|
| 后端 → 前端 | `{"type": "board", "delta": "..."}` | 板书文本增量（已去 `[text]:` 前缀） |

## 测试策略

- **后端单元测试**（fake WebSocket）：
  - 板书回合：音频被丢弃、`interrupt` 恰好一次、`board` 增量去前缀、字幕无泄漏
  - 普通回合：暂存正确补发，行为与现状一致
  - `response.done` 后复位，下一回合适配两种模式
  - 板书文本以原文落盘（on_final_transcript 收到 `[text]:…`）
  - `start` / `update_settings` 下发的 instructions 含 BOARD_PROMPT
- **前端**：手工验收（布局、拖拽、开关、追加、清空、历史渲染）
- **端到端**：真实端点讲一句"把勾股定理写到黑板上"，确认黑板出内容、无语音

## 已否决的替代方案

- **每回合后台调文本模型生成板书**：内容可与语音完全独立，但每回合
  多一次模型调用、黑板更新滞后 1~3 秒。用户选择了单模型标记方案。
- **语音指令触发**（"板书：…"）：可作为后续增强，本期不做。
